     8→# Android Guru Agent
     9→
    10→### 🤖 原生于 Android 的自主智能体 —— 设备上的大脑、终端、与肌肉记忆
    11→
    12→**An autonomous AI agent that lives entirely on your Android device.**
    13→
    14→一个开源的 Android 端自主智能体应用：OpenAI 兼容流式 LLM 接入、8 种执行模式（v3 新增 Goal 目标循环 / Loop 循环与 Cron）、
    15→111 个内置工具（v3 新增超时/重试/限流/熔断/追踪/批量/组合动作八层执行硬化；P83 环境闭环补全；MCP/技能按工位作用域隔离）、PRoot 沙箱化 Ubuntu 终端、仿生认知记忆系统（差分摄取 → 轨迹蒸馏 →
    16→FSM 旁路回放 → 梦境巩固）、Root/Shizuku/无障碍三级权限链、插件化 SDK ——
    17→全部跑在一台手机上，无需任何服务器。

   205→## ✨ 项目亮点
   206→
   207→| | 亮点 | 说明 |
   208→|:---:|------|------|
   209→| 🧠 | **仿生认知记忆** | UI 感知 → 语义降维（体积压缩 90%+）→ 差分摄取（再压缩 95%+）→ ReAct 轨迹蒸馏为有限状态机 → **0 token 的"肌肉记忆"旁路回放**，App 升级后经拓扑同胚迁移保鲜 |
   210→| 🛡️ | **记忆免疫系统** | 悬浮窗钓鱼 / 无障碍劫持 / 记忆中毒防御：敏感词分级 + 结构完整性校验 + 可疑指纹隔离（Quarantine） |
   211→| 🌙 | **梦境渲染** | 息屏 + 充电 + WiFi 时后台巩固记忆：低能宏保鲜验证、能量衰减、跨版本拓扑迁移（借鉴人类睡眠记忆巩固） |
   212→| 🔥 | **能量遗忘与晶化** | 每条记忆带能量值：使用增能、时间衰减、低能坍缩删除；能量≥8 且成功率≥90% 的高频宏**晶化为 ROM 级永久技能**，免疫衰减与剪枝 |
   213→| 🖥️ | **真·Linux 终端** | 设备上供给 Ubuntu 24.04 官方 rootfs，PRoot 用户态沙箱执行 + 原生 C++ PTY（forkpty/JNI）+ 自研 VT100/ANSI 模拟器，`apt install`、跑 bash 脚本皆可 |
   214→| 🔀 | **双引擎工作流** | 直连 ReAct 引擎 + 任务编排器（状态机/恢复规划/用户交互门/多模型路由）两条执行路径，复杂任务自动上编排 |
   215→| 🗜️ | **上下文工程** | 三级压缩（工具输出智能截断 → 滑动窗口 → LLM 摘要），双引擎统一水位检查，长任务不爆上下文窗口 |
   216→| 🛰️ | **BYO-LLM** | OpenAI 兼容协议 + DeepSeek / OpenRouter / Ollama / 自定义端点预设；多模型运行时按角色路由（含图片自动走 VISION）；原生支持 `reasoning_content` 思维链（R1 / Qwen3-thinking / o 系列） |
   217→| ⚡ | **三级权限链** | Root → Shizuku → 普通沙箱 shell 自动降级选择，无 Root 设备也能执行特权命令 |
   218→| 🧩 | **全插件化** | AIDL 跨进程插件 SDK + 技能市场（工具/技能/MCP/插件/连接器五个货架）+ 40+ 可安装技能模板 |
   219→| 💭 | **七档思考系统（Coding 页专属）** | NONE→ULTRACODE→APEXCODE 七深度档 + AUTO 预检自适应（发送前选档 + 深水区升级）；档位驱动提示词 / 模型参数 / 迭代倍率 / 压缩阈值 / 输出预算**全执行画像**，档位效能用历史数据说话（Agent 聊天页为独立六档体系） |
   220→| 🕓 | **长任务中心（v1.2）** | 超阈值运行自动留档；检查点时间线回看（轮次 / 相对时间 / todo 完成度）+ 续跑不从头、复制带上下文重跑、同目标运行对比、8 模板一键启动 |
   221→
   222→> [!IMPORTANT]
   223→> **这一切跑在一台普通 Android 手机上。** 不需要服务器，不需要 PC 伴侣，
   224→> 配置任意 OpenAI 兼容 API（或局域网 Ollama）即获得完整的智能体能力。

   231→## 🆚 与其他方案对比
   232→
   233→| 维度 | **Android Guru Agent** | PC 端编码智能体（Claude Code / OpenHands 等） | 传统自动化工具（Tasker 类） | 手机 AI 聊天 App |
   234→|------|------------------------|--------------------------------|------------------------------|------------------|
   235→| 运行位置 | 📱 全程在设备上 | 💻 PC / 服务器 | 📱 设备上 | ☁️ 云端 |
   236→| 需要服务器/PC | ❌ 不需要 | ✅ 需要 | ❌ 不需要 | ✅（厂商云） |
   237→| LLM 可换性 | ✅ 任意 OpenAI 兼容端点 / 局域网 Ollama | 固定模型或自配 | 无 LLM | ❌ 固定 |
   238→| 执行能力 | 102 工具：shell / 文件 / 结构化查询 / UI 自动化 / 浏览器 / 终端 | 文件 + shell + web | 规则触发，无推理 | 仅对话 |
   239→| Linux 环境 | ✅ PRoot Ubuntu 24.04 沙箱 | ✅ 宿主 OS | ❌ | ❌ |
   240→| 跨会话记忆 | ✅ 认知记忆：陈述性（语义图）+ 程序性（FSM 宏旁路回放） | 仓库内文件（CLAUDE.md 等） | ❌ | 云端会话 |
   241→| 离线记忆 | ✅ Room 本地图数据库 | — | — | ❌ |
   242→| 特权操作 | Root / Shizuku / 沙箱三级降级 | 宿主用户权限 | 需 Root 的居多 | ❌ |
   243→| 可扩展 | 插件 APK（AIDL）+ 技能 + MCP | MCP 等 | 插件市场 | ❌ |
   244→
   245→> [!NOTE]
   246→> 对比基于各方案公开形态的定性归纳；PC 端智能体在代码工程深度上依然更强，
   247→> 本项目的差异化在于**把完整的智能体闭环装进口袋**。

   345→## 🧠 认知记忆系统 cs-mem
   346→
   347→`platform/cs-mem` 是本项目的差异化核心：它不只是"给 LLM 塞一段历史"，
   348→而是一套把 **屏幕感知转化为可复用程序性记忆** 的完整管线。
   349→
   350→### 管线全景
   351→

   353→flowchart TB
   354→    subgraph INGEST["🔵 摄取侧 —— 每次动作后自动触发"]

   357→        B["✂️ 语义降维<br/>UiTreePruner<br/>剔除不可见与装饰节点<br/>体积 -90%+ · 指纹 SHA-256"]
   358→        C["Δ 差分摄取<br/>DifferentialIngestor<br/>只存状态跃迁<br/>压缩 95%+"]
   359→        D["✉️ 串行写入<br/>MemoryWriterActor<br/>有界邮箱 256 · 背压"]
   360→        A --> B --> C --> D
   361→    end
   362→

   364→    D --> E
   365→
   366→    subgraph CONSUME["🟢 消费侧"]

   373→
   374→    E --> R1
   375→    E --> R2
   376→
   377→    IMM["🛡️ MemoryImmuneSystem<br/>摄取前免疫检查<br/>悬浮窗 / 敏感词 / 完整性 / 隔离"] -.检查.-> INGEST

   381→### 记忆的两种形态
   382→
   383→| 形态 | 模型 | 产生 | 消费 |
   384→|------|------|------|------|
   385→| **陈述性记忆** | `SemanticNode` 语义图 + `Episode` 情景 + `GraphEdge`（SPATIAL/CAUSAL/SEMANTIC 三类边） | 每次动作后 `CsMemSessionManager.afterAction()` 捕获差分 | `memory_search_nodes` / `memory_recent_episodes` 召回工具；记忆屏可视化 |
   386→| **程序性记忆** | `FSMMacro` 有限状态机宏技能 | 任务成功后 `TraceDistiller.distill()`：锚点提取 → 动作压缩 → FSM 编译 | `BypassExecutionEngine.tryBypass()`：指纹命中即**绕过 LLM 直接回放**（微秒级 / 0 token） |
   387→
   388→### 生命周期管理（四个仿生机制）
   389→
   390→| 机制 | 组件 | 触发 | 效果 |
   391→|------|------|------|------|
   392→| 🔥 **能量熵增** | `EntropyManager` | 每次梦境周期 | 成功检索/执行 → 能量增加；时间推移 → 指数衰减（艾宾浩斯遗忘曲线） |
   393→| 💎 **晶化** | `EntropyManager.shouldCrystallize` → `crystallizeMacro` | 能量≥8 且成功≥10 次且成功率≥90% | ROM 级固化：免疫衰减/剪枝/删除 |
   394→| 🌙 **梦境渲染** | `DreamRenderer`（WorkManager） | 息屏 + 充电 + WiFi + 电量≥50% | 低能宏随机保鲜验证、全局熵衰减、拓扑同胚迁移 |
   395→| 🛡️ **免疫** | `MemoryImmuneSystem` | 每次摄取前 | 悬浮窗检测 / 敏感词分级 / 结构完整性 / 包名可信分级 / 可疑指纹隔离 |
   396→
   397→### 跨版本记忆保鲜（拓扑同胚迁移）
   398→
   399→App 升级会改变 UI（resourceId / 布局 / 文案）→ 旧指纹失效 → 宏集体失配。
   400→解法是**别名桥**而不是改写历史：
   401→
   402→```mermaid
   403→flowchart TB
   404→    D["🌙 梦境周期<br/>TopologyMigrator"] --> CMP["对比旧/新版本节点集<br/>同 role + resourceId 归一化<br/>+ textHint 相似度打分 ≥ 0.7"]
   405→    CMP --> MAP["migration_map<br/>old_fp → new_fp<br/>（score · from_version → to_version）"]
   406→    MAP --> LOOKUP["召回侧：精确匹配失败时<br/>findMacrosViaMigration 反查旧别名"]
   407→    LOOKUP --> RES["resolveMigration 正向校验闭环<br/>resolve(旧指纹) == 探测指纹"]
   408→```

   410→### 存储演化（schema v3）
   411→
   412→- 边 ID 从**帧内自增计数器**改为**内容哈希**（SHA-256(源指纹\|目标指纹\|关系) 前 16 位）——
   413→  同一条拓扑边在任意两帧同 ID，差分语义与跨 Episode 删除才正确；
   414→- v2→v3 Room 迁移：清理历史重复边 + 建 `(episode_id, edge_label)` 唯一索引 + 删除增加 episode 作用域；
   415→
   416→> [!WARNING]
   417→> 升级必须显式提供 Room `Migration`，仅降级允许 destructive 重建 ——
   418→> 这是保护长期记忆不被静默清空的硬约束。

   428→<a id="engine"></a>
   429→## 🔄 Agent 引擎与六种工作模式
   430→
   431→`core:agent-engine` 提供两条执行路径，UI 自动选择：
   432→
   433→1. **直连路径 `ApexAgentEngine`** —— 流式 ReAct 循环（Think → Act → Observe → …），
   434→   全事件流输出，适合绝大多数对话式任务；
   435→2. **编排路径 `DefaultTaskOrchestrator`** —— 复杂长任务：任务状态机、
   436→   批量工具执行引擎、失败分类 + 恢复规划器、重试策略、循环检测（LoopDetector）、
   437→   用户交互门（ask_user 挂起等待人工决策）、生命周期事件（SharedFlow）。
   438→
   439→### 编排器任务状态机（真实转移）
   440→
   441→```mermaid
   442→stateDiagram-v2
   443→    direction LR
   444→    [*] --> Idle
   445→    Idle --> Planning : execute(mode)
   446→    Planning --> AwaitingPlanConfirmation : PlanGenerated
   447→    AwaitingPlanConfirmation --> Planning : 确认 / 重规划
   448→    Planning --> AwaitingSpecConfirmation : SpecGenerated
   449→    AwaitingSpecConfirmation --> Planning : 确认 / 重规划
   450→    Planning --> Acting : ToolCallScheduled
   451→    Acting --> Observing : ToolCallFinished
   452→    Observing --> Planning : 下一轮迭代
   453→    Observing --> Responding : 无更多工具调用
   454→    Acting --> AwaitingUserInput : ask_user / 权限门
   455→    AwaitingUserInput --> Acting : 用户答复
   456→    Responding --> Completed : ResponseComplete
   457→    Planning --> Failed : 异常 / 重试耗尽
   458→    Acting --> Failed : 批量执行失败
   459→    Observing --> Failed : 恢复规划失败
   460→    Responding --> Failed : LLM 错误
   461→    Planning --> Aborted : cancel
   462→    Acting --> Aborted : cancel
   463→    Responding --> Aborted : cancel
   464→    Completed --> [*]
   465→    Failed --> [*]
   466→    Aborted --> [*]
   467→```
   468→
   469→> [!NOTE]
   470→> 图为 `TaskStateMachine` + `DefaultTaskOrchestrator` / `BatchExecutionEngine`
   471→> 中全部 `transitionTo(...)` 调用的合并视图；`Finished` 是 sealed 终态
   472→> （Completed / Failed / Aborted），终态不可逆。

   474→### 六种模式（`AgentMode`）
   475→
   476→| 模式 | 行为 | 适用 |
   477→|------|------|------|
   478→| **Build** | 边想边做，实时执行 | 简单任务、快速响应 |
   479→| **Plan** | 先产出完整计划，用户确认后逐步执行 | 复杂多步操作 |
   480→| **Spec** | 先产出需求规格（目标/需求/约束/验收标准/交付物），确认后逐项执行 | "做什么、做成什么样才算完成" |
   481→| **Reflect** | 生成 → 评审 → 修正 自我循环 | 代码生成、内容创作等高质量场景 |
   482→| **Assist** | 遇到多选（方案/目标/偏好）强制弹出选项菜单人工决策 | 不擅自猜测的谨慎场景 |
   483→| **Custom** | 附加用户自定义指令（输出格式/语言/行为约束），持久化保存 | 个性化定制 |
   484→
   485→### 双层思考深度（v1.2：7 档 + AUTO）
   486→
   487→| 层 | 控制点 | 档位 | 效果 |
   488→|----|--------|------|------|
   489→| **提示词思考** | Agent 六档 `ThinkingLevel` / Coding 七档 `CodeThinkingLevel` | 两套独立阶梯：聊天页 NONE/LIGHT/STANDARD/DEEP/MAXIMUM+AUTO；Coding 页另有 ULTRACODE/APEXCODE 深水两档 | 系统提示注入推理指令强度；档位同时驱动**执行画像**（迭代倍率 / 压缩阈值 / 输出预算，Coding 深水两档经旋钮补偿反补） |
   490→| **原生思考** | `ReasoningEffort` | NONE / LOW / MEDIUM / HIGH / MAX | 直接写 `reasoning_effort` 请求参数（o 系列 / R1 / Qwen3-thinking），MAX 档同时抬高 `max_completion_tokens` 给思维链留空间 |
   491→
   492→**七档思考阶梯**（**Coding 页专属**；Agent 聊天页为独立六档体系，两页面互不干扰。Code 屏另有「思考档位指南」弹层摊开全部画像 + 档位效能统计）：
   493→
   494→| 档位 | 定位 | budget | 迭代倍率 | 输出预算 |
   495→|------|------|--------|----------|----------|
   496→| NONE | 直接执行不推理 | 0 | ×0.8 | 6000 |
   497→| LIGHT | 1-2 句简思 | 256 | ×0.9 | 7000 |
   498→| STANDARD | CoT 三步 | 1024 | ×1.0 | 8000 |
   499→| DEEP | 多路径 5 步 + 工具失败自检 | 4096 | ×1.2 | 9000 |
   500→| MAXIMUM | ToT 7 步 + 终检三问清单 | 16384 | ×1.5 | 10000 |
   501→| ULTRACODE | 编码闭环 7 步（不变量→候选改法→风险排序→最小修改→即时验证） | 32768 | ×2.0 | 12000 |
   502→| APEXCODE | 架构级穷举 + 对抗性自审 + 全量验证矩阵 + 证据链汇报 | 65536 | ×3.0 | 16000 |
   503→| AUTO | 元档：发送前预检选档 + 深水区升级（可升至 ULTRACODE，**永不自动选 APEXCODE**） | — | — | — |
   504→
   505→Coding 模式在通用画像之上还有一层**编码特化指令**（`CodeThinkingPrompts`：
   506→一读一改 / 标准编码循环 / 改动集思维 / 不变量守护 / 依赖地图→回归扫描 /
   507→影响半径测绘→证据链汇报）——「怎么想」与「编码时具体怎么想」三层分工，
   508→互不重复注入。
   509→
   510→两层**正交**：可以 NONE+MAX（纯模型原生思考）也可以 DEEP+NONE（纯提示引导）。
   511→原生思维链通过 `LlmStreamChunk.reasoningContent` 透传为 `ThinkingChunk` 事件，
   512→UI 实时显示推理过程（正文与思维链严格分流，双引擎同语义）。

   514→### 多模型运行时（T72）
   515→
   516→- `ModelRoleRouter`：按角色（默认/VISION）路由到不同模型；
   517→- 会话含图片时自动要求 `vision + imageInput` 能力，全链无视觉模型则抛
   518→  `ModelCapabilityMismatch`（能力校验 + 诚实降级）；
   519→- `ModelProfileValidator` 校验档案，`ErrorClassifier` 分类运行时错误供重试决策。
   520→
   521→### 🧑‍💻 Coding 模式（Code 屏 —— 与 Agent 模式同级别的对等入口）
   522→
   523→与六种 `AgentMode`（会话行为开关）不同，**Coding 模式是一个独立的顶层工作面**：
   524→抽屉里的 Code 屏拥有自己的引擎实例、按工作区隔离的会话记忆、以及业界标准
   525→契约的编码工具集 —— 但与 Agent 模式**共享全部能力基础设施**（工具注册表 +
   526→v3 执行硬化 + v4 目录 / 技能注入 / MCP 一等工具 / 插件 / 多模型路由）。
   527→
   528→```text
   529→┌─ Code 屏（app/ui/screen/code）──────────────────────────────────┐
   530→│ 工作区条（切换/新建/删除 + 环境探测摘要）                          │
   531→│ Todo 面板（code_todo 实时快照 → checklist 渲染）                  │
   532→│ 消息流（用户 / 助手 Markdown / 工具卡 diff 着色 +/-）              │
   533→│ 输入栏（发送 / 停止 / ask_user 应答）                             │
   534→└──────────────────────────────────────────────────────────────────┘
   535→        │ @Named("code") 独立引擎实例（CodeAgentEngine）
   536→        ▼
   537→┌─ core/code-engine ──────────┐   ┌─ core/code-tools（6 工具）────┐
   538→│ CodePrompts（编码行为注入）   │   │ code_read   行号契约+目录+纠错  │
   539→│ CodeConversationMemory      │   │ code_edit   7级模糊替换链+护栏   │
   540→│ （per-workspace 会话记忆）    │   │ code_write  全量写+diff 回显    │
   541→│ JIT 上下文（环境/统计注入）    │   │ code_grep   ripgrep 语义搜索    │
   542→└─────────────────────────────┘   │ code_glob   递归模式匹配        │
   543→        │ 共享单例                 │ code_todo   任务清单状态机      │
   544→        ▼                         └────────────────────────────────┘
   545→┌─ platform/code-workspace ───┐   ┌─ MCP（BUILTIN 进程内服务器）────┐
   546→│ 工作区生命周期 + 环境探测      │   │ search：web_search/web_fetch    │
   547→│ 默认工作区=Agent 沙箱同源目录  │   │ （Agent/Code 两模式互用）       │
   548→│ host↔guest(/workspace) 同一文件│  └────────────────────────────────┘
   549→└─────────────────────────────┘
   550→```
   551→
   552→**关键设计**：
   553→
   554→- **不重写 Agent Loop** —— `CodeAgentEngine` 是 `ApexAgentEngine` 的薄包装，
   555→  编码行为经 `additionalSystemContext` 通道注入（BUILD 循环 + 业界标准风格
   556→  编码行为段落），Agent 模式零影响；
   557→- **code_edit 的成功率就是编码循环的效率** —— 精确匹配失败后依次尝试
   558→  行 trim / 块锚点+Levenshtein / 空白归一 / 缩进平移 / 边界 trim / replaceAll
   559→  七级回退；失衡护栏（模糊命中 span 远大于 old_string 时拒绝）防止"吞代码"；
   560→- **工作区即沙箱** —— code_* 工具的根经 `CodeWorkspaceRoots` 动态解析，
   561→  切换工作区即时生效；默认工作区与 Agent 文件工具、Ubuntu 终端会话三方
   562→  看同一份文件（`linux/workspaces/default` ↔ guest `/workspace`）；
   563→- **网络搜索 MCP 本地运行** —— `BuiltinSearchMcpTransport` 把成熟搜索栈
   564→  （DuckDuckGo/Bing 三级回退 + 智能正文提取）包装为进程内 MCP 服务器，
   565→  Agent 与 Coding 两模式共享 `mcp__search__web_search` 一等工具。
   566→
   567→### 🕓 长任务中心（v1.2）
   568→
   569→跑完即散是深度任务的死穴：几十轮迭代的重构 / 修 Bug / 评审一旦会话清理
   570→就全部蒸发，想「再来一遍」只能从头描述。Code 屏工作区条的「长任务」入口
   571→把达到规模阈值（迭代 ≥8 / 工具 ≥12 / 时长 ≥120s / 文件 ≥3，四维任一达标，
   572→`LongTaskDetector`）的运行**自动留档**，并在其上提供六类顶级操作：
   573→
   574→| 能力 | 说明 |
   575→|------|------|
   576→| 🕓 **检查点时间线** | 运行中每 5 轮 / 60s 拍一张廉价快照（≤10 个，超限丢最旧）；展开记录卡即是时间线渲染——轮次徽标 + 相对时间（+45s）+ 累计计数（工具 / 文件）+ monospace 对话摘要 + todo 完成度（☑3 ☐2），上次卡在哪、绕了哪些弯一眼可见 |
   577→| 📋 **复制任务** | 携带上次的结论再跑：上下文 / todo 快照 / 文件清单三开关 + 档位覆盖（用 ULTRACODE 重跑 DEEP 任务做对比）+ 跨工作区复制 + 复制链谱系（`parentTaskId` 溯源整条重跑历史） |
   578→| ⏯️ **检查点续跑** | 不从头重跑——从指定检查点（或最后检查点）接着干，上次的弯路不重走；无检查点时诚实回退为带上下文重跑 |
   579→| 🔄 **运行对比** | 同 parent 的兄弟记录天然是「同一目标的不同尝试」，`LongTaskDiff` 产出迭代 / 工具 / 时长 / 文件集的结构化对比报告 |
   580→| 🗂️ **8 内置模板** | 重构 / 修 Bug / 新功能 / 评审 / 测试 / 文档 / 性能 / 迁移——应用推荐思考档位 + 预置 todo 骨架，一键启动 |
   581→| 📊 **档位效能** | 工作区 × 思考档位的长任务聚合统计（runs / 成功率 / 平均迭代 / 工具 / 时长）——用自己的历史数据选档，而非凭感觉 |

   587→<a id="context-compression"></a>
   588→## 🗜️ 上下文工程（P7 三级压缩）
   589→
   590→长任务的死穴是上下文窗口。双引擎共享同一套 `HybridCompressor`，在
   591→`TokenEstimator` 估计超阈值（默认 128k×80%）时逐级触发：
   592→
   593→```mermaid
   594→flowchart TD
   595→    IN["新工具输出 / 新一轮迭代"] --> W{"水位检查<br/>TokenEstimator > 128k × 80% ?"}
   596→    W -- 否 --> KEEP["保持原样"]
   597→    W -- 是 --> C1["Layer 1 · ToolOutputTruncator（零成本 · 永远在跑）<br/>JSON → 保头 + 尾 200 字符（闭合结构）<br/>列表多于 20 短行 → 保首 15 + 尾 10 行<br/>read_file 类 → 只保头<br/>默认 → 头 1200 + 尾 600 字符 + 省略标注"]
   598→    C1 --> W2{"仍超阈值？"}
   599→    W2 -- 否 --> DONE1["✅ 完成"]
   600→    W2 -- 是 --> C2["Layer 2 · SlidingWindowCompressor（零成本）<br/>保系统提示 + 最近 N 轮<br/>中段折叠为单条规则摘要"]
   601→    C2 --> W3{"仍超阈值？"}
   602→    W3 -- 否 --> DONE2["✅ 完成"]
   603→    W3 -- 是 --> C3["Layer 3 · LlmSummaryCompressor（一次额外 LLM 调用）<br/>中段结构化摘要（Task / Progress / State / Key Data ≤400 词）<br/>失败自动回退规则摘要"]
   604→```
   605→
   606→> [!NOTE]
   607→> **永不压缩**：系统提示 / 最新用户任务 / 最近 5 轮 / 执行中工具调用。
   608→> 压缩后发射 `AgentEvent.ContextCompressed(before, after, strategy, ...)`，
   609→> UI 渲染为系统消息，压缩结果同步回持久化记忆（重启后加载已压缩状态）。

   628→| 包管理 | `UbuntuAptPackageManager` + `PackageOperationLock` | 设备上 `apt install`，并发锁防交错 |
   629→| 环境自适应 | `AdaptiveProvisionLoop` + `DiagnosticRules` | 执行观察 → 诊断规则 → 自动修复（ResolverCache） |
   630→| 会话持久化 | `SessionMetadataStore` + `RuntimeRecoveryService` | 重启恢复会话元数据 |

   822→<a id="liquid-glass"></a>
   823→## 💎 Liquid Glass 玻璃组件系统
   824→
   825→普通 Android UI + 精确使用的 Liquid Glass 组件，而非“整个 App 一坨透明塑料”：
   826→
   827→- **两个诚实材质档**：Backdrop 档经 [Haze](https://github.com/chrisbanes/haze) 以 `GraphicsLayer` 真实采样背后内容（API 32+ 走 GPU `RenderEffect` 模糊，低版本自动 scrim 降级）；Frosted 档仅主题色薄霜 + 边缘光 + 高光，不冒充 backdrop
   828→- **七档材质**：`Subtle / Control / Card / Navigation / Floating / Dialog / Strong`，tint、边缘、高光、噪声全部从 MaterialTheme 动态派生，Light / Dark / Dynamic Color 自适应
   829→- **已玻璃化**：抽屉导航项（悬浮于氛围背景之上）、聊天悬浮输入栏（采样消息流）、回到底部 FAB、工具卡 / 计划卡 / 任务状态卡、顶栏菜单钮、玻璃对话框（HazeDialog 跨窗口采样）
   830→- **明确不玻璃化**：终端渲染区（性能敏感）、页面背景、气泡正文
   831→- **未实现即声明**：Refraction（折射位移）明确标注 NOT IMPLEMENTED，拒绝“alpha + blur 冒充玻璃”
   832→
   833→组件 API 与验收细则见 [docs/liquid-glass-system.md](docs/liquid-glass-system.md)，抽屉内“玻璃实验室”屏可真机验证 backdrop / blur / 边缘 / 交互。

   863→## 🚀 快速开始
   864→
   865→### 环境要求
   866→
   867→| 依赖 | 版本 | 说明 |
   868→|------|------|------|
   869→| JDK | 17 | Temurin 推荐 |

   872→
   873→### 构建
   874→
   875→```bash
   876→git clone https://github.com/AceGuru-mjh/Android-Guru-Agent.git
   877→cd Android-Guru-Agent
   878→
   879→# 仓库未锁定 wrapper——用本机 Gradle 8.10 现场生成（仅首次）：
   880→gradle wrapper --gradle-version 8.10
   881→chmod +x gradlew
   882→
   883→./gradlew :app:assembleDebug --stacktrace
   884→```
   885→
   886→> [!TIP]
   887→> 不想自己构建？**直接下载正式版**：[发布仓库 Releases](https://github.com/AceGuru-mjh/Android-Guru-Agent-Release/releases/latest)
   888→> （arm64 / universal 两个变体；**PR 合并进 main 即自动构建发布**，无需打 tag）。
   889→> 已装用户可在 App「设置 → 关于 → 检查更新」直接升级 —— 支持增量补丁
   890→> （~14MB vs 全量 300MB+）与高速节点/镜像加速下载；补丁下载后**应用内自动
   891→> 合成新版本并拉起安装**（纯 Kotlin VCDIFF 解码器，零命令行），跨任意多个
   892→> 小版本自动按 [patches.json](https://github.com/AceGuru-mjh/Android-Guru-Agent-Release/blob/main/patches.json)
   893→> 补丁链逐段升级。
   894→> 也可以用 CI 的 `app-debug-apk` 工件（debug 构建，保留 14 天）；或参考
   895→> `.github/workflows/ci.yml` 的 `Configure pre-installed Android SDK` 步骤配置环境。
   896→
   897→产物：`app/build/outputs/apk/debug/app-debug.apk`。
   898→
   899→### 配置智能体
   900→
   901→1. 安装启动 → 抽屉「设置」；
   902→2. 选择预设（OpenAI / DeepSeek / OpenRouter / Ollama / 自定义）；
   903→3. 填 Base URL + API Key + 模型名（局域网 Ollama 填 `http://<pc-ip>:11434`）；
   904→4. 点「测试连接」（发送 `Say 'OK' in one word.` 验证）→ 保存。
   905→
   906→未配置时注入 `NoOpLlmClient`，界面友好提示而不崩溃。

   911→  ADB 级权限（pm install / settings / input / dumpsys）；
   912→- **无障碍服务**：UI 自动化（ui_tap / ui_dump）与 cs-mem 屏幕感知；
   913→- **终端**：Ubuntu 24.04 完整 CLI 环境随 APK 内置（gcc/python3/git/vim/man，
   914→  rootfs 档案 ~300MB+，首次使用离线解包约 2~5 分钟；此后只有 apt 装新包才联网）。

  1083→<a id="faq"></a>
  1084→## ❓ FAQ
  1085→
  1086→<details>
  1087→<summary><b>1️⃣ 需要 Root 吗？</b></summary>
  1088→
  1089→**不需要。** 三级权限链会自动降级：无 Root 时优先用 Shizuku（ADB 级，
  1090→免 Root 装应用 / 改设置 / 模拟输入），再不行就用普通应用沙箱 shell。
  1091→Root 只是解锁全系统操作（`/system`、SELinux、ptrace 等）的上限增强。
  1092→
  1093→</details>
  1094→
  1095→<details>
  1096→<summary><b>2️⃣ 必须配置 API Key 吗？支持哪些模型？</b></summary>
  1097→
  1098→需要一个任意 OpenAI 兼容端点的 Key（OpenAI / DeepSeek / OpenRouter / 中转 /
  1099→局域网 Ollama 均可）。未配置时应用以 `NoOpLlmClient` 优雅降级、界面提示而不
  1100→崩溃。DeepSeek-R1 / Qwen3-thinking / o 系列的原生思维链（`reasoning_content`）
  1101→会透传到 UI 实时显示。
  1102→
  1103→</details>
  1104→
  1105→<details>
  1106→<summary><b>3️⃣ 我的 API Key 和记忆数据存在哪？会隐私泄露吗？</b></summary>
  1107→
  1108→- Key 与记忆全部只存**应用私有目录**（`filesDir` / SharedPreferences），
  1109→  不上传任何自有服务器——本项目没有服务器；
  1110→- GitHub PAT 经 `EncryptedSharedPreferences`（AES-256-GCM）加密存储；
  1111→- 会话内容会直连**你配置的 LLM 端点**（这是智能体工作的必要通道），
  1112→  用局域网 Ollama 即可做到全链不出内网。
  1113→
  1114→</details>
  1115→
  1116→<details>
  1117→<summary><b>4️⃣ 终端的 Ubuntu 会很费流量 / 存储吗？</b></summary>
  1118→
  1119→Ubuntu 24.04 完整 CLI 环境随 APK 内置（rootfs 档案 ~300MB+、解压后 ~1GB，
  1120→构建期 SHA-256 锁定），首次使用离线解包约 2~5 分钟；此后完全离线，
  1121→只有 `apt install` 装新包时才联网。PRoot 是用户态沙箱，
  1122→不修改系统分区。
  1123→
  1124→</details>
  1125→
  1126→<details>
  1127→<summary><b>5️⃣ 为什么仓库里没有 gradlew？</b></summary>
  1128→
  1129→仓库未锁定 wrapper。一条命令现场生成（见快速开始），或直接下载 CI 产出的
  1130→debug APK 工件（每次构建保留 14 天），零环境开箱体验。
  1131→
  1132→</details>
  1133→
  1134→<details>
  1135→<summary><b>6️⃣ "肌肉记忆"是什么意思？真的省 token 吗？</b></summary>
  1136→
  1137→任务成功后，`TraceDistiller` 把 ReAct 轨迹蒸馏成 FSM 宏技能。之后再次遇到
  1138→相同界面指纹时，`BypassExecutionEngine` 直接回放动作序列——**完全绕过 LLM**，
  1139→0 token、微秒级返回。App 升级导致指纹漂移时，拓扑同胚迁移通过别名桥保鲜。
  1140→
  1141→</details>

  1147→<a id="glossary"></a>
  1148→## 🧭 术语速查
  1149→
  1150→| 术语 | 一句话解释 |
  1151→|------|-----------|
  1152→| **cs-mem** | 本项目的认知记忆系统（cognitive memory）：屏幕感知 → 语义图 + FSM 宏技能 |
  1153→| **差分摄取** | 只存 UI 状态之间的"跃迁"，而不是整帧快照，压缩 95%+ |
  1154→| **节点指纹** | UI 节点的 SHA-256 内容哈希，是记忆索引与宏回放匹配的主键 |
  1155→| **FSM 宏** | 把成功任务轨迹编译成的有限状态机技能，可 0 token 旁路回放 |
  1156→| **晶化** | 高能量高成功率的宏固化为 ROM 级永久技能，免疫遗忘与剪枝 |
  1157→| **梦境渲染** | 息屏+充电+WiFi 时的后台记忆巩固周期（保鲜验证/衰减/迁移） |
  1158→| **PRoot** | 用户态 ptrace 沙箱，免 Root 运行完整 Linux 发行版 |
  1159→| **PTY** | 伪终端（C++ forkpty 实现），交互式 shell 的底层通道 |
  1160→| **VT100/ANSI** | 终端转义序列标准，自研模拟器负责渲染与解析 |
  1161→| **Shizuku** | 通过 ADB 授权获得 uid=2000 权限的框架，免 Root 执行特权命令 |
  1162→| **MCP** | Model Context Protocol——外部工具服务器的标准接入协议 |
  1163→| **BYO-LLM** | Bring Your Own LLM：自带任意 OpenAI 兼容端点与 Key |
  1164→| **AIDL** | Android 接口定义语言，插件 APK 与宿主跨进程通信的契约 |
  1165→| **P7 三级压缩** | 工具输出截断 → 滑动窗口 → LLM 摘要的上下文预算防线 |
